## 0. Özet ve kapsam sınırı

### 0.1 Terimler
- **Masraf (expense):** ZTO `ZT_ProductionExpenses` kaydının karşılığı. Tek bir masraf faturası/fişidir; satırları `expense_line` tablosundadır. Bağlamı (`context_type`) GENERAL, VEHICLE, SHIPMENT, WAREHOUSE ya da DRIVER olabilir. Şirket ve iş yeri her zaman doludur.
- **Masraf kalemi (expense_item):** gider sınıflandırmasıdır. ZTO'daki "kalem = cari kart" deseni **ÇIKAR** (MX4 A.4). Borç, tedarikçi carisine yazılır.
- **Taşeron gideri:** `trip_cost` satırı. `kind = SUBCONTRACTOR` ve taşerona verilmiş bir etaba (`shipment_leg.carrier_account_id`) bağlıdır.
- **Ödenecek (payable):** cariye yazılan tutardır.
  - Taşeron: `amount + vat_amount − withholding_amount − deduction_amount`.
  - Masraf: `total_amount`.

### 0.2 12.7'de YAPILACAK
1. **Migration'lar.** Z20 → `V39__trip_cost_subcontract.sql`, Z21 → `V40__expense.sql` (§1).

### 0.4 MX4 / MX8 / keşiften sapmalar (bu belge geçerlidir)
- **V numaraları.** MX4 V22/V34 ve MX8 V2xR1 geçersiz. Z20 = V39, Z21 = V40.
- **Bağlam.** MX4'teki çok biçimli `context_id` yerine tipli FK kolonları kullanılır: `vehicle_id`, `shipment_id`, `warehouse_id`, `driver_id` + `num_nonnulls` CHECK. `document_file_id` yok; belge `stored_file(owner_type='EXPENSE', owner_id)` ile bağlanır (12.3 deseni). `purchase_invoice_id` yok.
- **Ödeme şekli.** ZTO'da yok; yeni zorunlu alan: `payment_method` ACCOUNT, CASH ya da BANK. ZTO'da "kalem = cari" olduğu için borç kaleme yazılıyordu.
- **Etiket.** PEA "Masraf Cari Hesap" etiketi **"Masraf Kalemi"** olur, çünkü anlam değişti (Y9'a tek istisna).
- **Taşeron uçları.**
  - MX8'deki `PUT /shipment/costs/{id}` ve `POST /shipment/costs/{id}/post` yerine tek uç: `PUT /shipment/shipments/{id}/legs/{legId}/subcontract-cost` (kaydet + cariye işle).
  - Ters kayıt ucu `POST /shipment/subcontract-costs/{costId}/reverse`.
  - `companyInfoModal` UI-API değil, ÇIKAR.
- **Diğer Vergiler.** ZTO PEA:1340 TOPLAM'dan **düşüyor**, burada **eklenir**: `toplam = net + KDV + diğer − tevkifat`. 04 §7'ye yeni madde (§7, koordinatör).
- **Para birimi kırılımı.** PEI "Tüm Zamanlar…", STI "Toplam Tutar" ve PEL "Toplam Masraf" kartları farklı para birimlerini ₺ ile topluyor. Burada para birimi kırılımlı gösterilir.
- **TOPLAM satırı.** STI ve CSD'de `tbody` içindeki TOPLAM satırı `tfoot`'a taşınır.
- **Tablo ve düğmeler.**
  - CSD tablo id'si `dataTable2` (MX8 `salesDetailsTable` diyor).
  - CSD `edit-sales-button` (CSD:701) eklenir.
  - STI'den detaya geçiş satır tıklamasıyla değil, "Araçlar ve Detaylar" düğmesiyle olur.
- **Gün varsayılanı.** Tek varsayılan **150** gün (CSD yeniden yüklemede 90 kullanıyor).
- **Pasifleştirme.** ExpenseItems "Sil" aslında aktif/pasif değiştirir (ZTO EIC:549-653). Burada `PUT …/active` ucuyla aynı davranış uygulanır; ancak sistem kalemi pasifleştirilemez.

### 0.5 Değişmezlik güvenceleri (testle doğrulanır, §6)
- **Tek yazıcı.** Cari hareketini yalnız `LS.post/reverseSource`, fon hareketini yalnız SS (→ `FundLedgerService`) yazar. Yeni defter yazarı yoktur.
- **Kaynak türleri.** `TRIP_COST` (mevcut) ve `EXPENSE` (yeni). Idempotency `account_transaction UNIQUE (source_type, source_id)` (V3) ve settlement idempotency anahtarı `EXPENSE:{expenseId}` ile sağlanır. Düzeltmede yeni satır yeni `id` ile yazılır.
- **Net tutar.** `trip_cost.amount` ve `tl_amount` **net** kalır. `ReportService` (BASE:51-63) ve `TFS.profitRows` değişmez; ters çevrilen satır `deleted = true` olduğu için dışarıda kalır.
- **Saklı bakiye yok.** Satır silinmez; iptal = ters kayıt + `status = 'REVERSED'` + `deleted = true` (`vehicle_expense` deseni).
- **Kapanış.** `TFS.close` yalnız `status = 'OPEN'` satırları yazar. KDV vb. alanlar 0 olan eski satırlarda tutar aynı kalır.

### 1.1 `MIG/V39__trip_cost_subcontract.sql` (Z20)

```sql
-- Z20 · Faz 12.7 · MX8 §1.7, §1.9 (V2xR1 taslağının yerine) · 12.7_TASARIM §1.1
-- Taşeron (SUBCONTRACTOR) sefer gideri: KDV, tevkifat, kesinti, belge, durum ve düzeltme zinciri.
-- amount/tl_amount NET kalır (kârlılık değişmez); cariye yazılan = amount + vat − withholding − deduction.
-- company_id eklenmez: şirket seferden türetilir (12.1a §2.3).

ALTER TABLE trip_cost
    ADD COLUMN vat_amount         NUMERIC(19, 4) NOT NULL DEFAULT 0,
    ADD COLUMN withholding_amount NUMERIC(19, 4) NOT NULL DEFAULT 0,
    ADD COLUMN deduction_amount   NUMERIC(19, 4) NOT NULL DEFAULT 0,
    ADD COLUMN document_no        VARCHAR(50),
    ADD COLUMN document_type      VARCHAR(40),
    ADD COLUMN cost_date          DATE,
    ADD COLUMN exchange_rate      NUMERIC(19, 6),
    ADD COLUMN status             VARCHAR(20)    NOT NULL DEFAULT 'OPEN',
    ADD COLUMN replaced_by_id     UUID REFERENCES trip_cost (id),
    ADD COLUMN reversed_on        DATE,
    ADD COLUMN reverse_reason     VARCHAR(500);

-- Dolu kiracı: kapanışta yazılmış satırlar POSTED; belge tarihi kayıt gününden.
UPDATE trip_cost SET status = 'POSTED' WHERE posted_at IS NOT NULL;
UPDATE trip_cost SET cost_date = created_at::date WHERE cost_date IS NULL;

ALTER TABLE trip_cost
    ADD CONSTRAINT trip_cost_vat_ck CHECK (vat_amount >= 0),
    ADD CONSTRAINT trip_cost_withholding_ck CHECK (withholding_amount >= 0 AND withholding_amount <= vat_amount),
    ADD CONSTRAINT trip_cost_deduction_ck CHECK (deduction_amount >= 0),
    ADD CONSTRAINT trip_cost_payable_ck CHECK (amount + vat_amount - withholding_amount - deduction_amount > 0),
    ADD CONSTRAINT trip_cost_status_ck CHECK (status IN ('OPEN', 'POSTED', 'REVERSED')),
    ADD CONSTRAINT trip_cost_reversed_ck CHECK ((status = 'REVERSED') = (reversed_on IS NOT NULL)),
    ADD CONSTRAINT trip_cost_rate_ck CHECK (exchange_rate IS NULL OR exchange_rate > 0);

CREATE INDEX trip_cost_account_idx ON trip_cost (account_id) WHERE deleted = FALSE;
CREATE INDEX trip_cost_leg_kind_idx ON trip_cost (leg_id, kind) WHERE deleted = FALSE;

-- Nakliye türü (ZTO "Sevk Nakliye" / "Gemi Nakliye").
ALTER TABLE shipment_leg
    ADD COLUMN transport_mode VARCHAR(10) NOT NULL DEFAULT 'ROAD',
    ADD CONSTRAINT shipment_leg_transport_mode_ck CHECK (transport_mode IN ('ROAD', 'SEA', 'RAIL', 'AIR'));
```

### 3.2 `ExpenseService` (B2, yeni; `BE/finance/service/ExpenseService.java`)
Bağımlılıklar: `ExpenseRepository`, `ExpenseLineRepository`, `ExpenseItemRepository`, `ExpenseCalculator`, `LedgerService`, `SettlementService`, `ExchangeRateService`, `CompanyResolver`, `BranchScopeService`, `CompanyIdentityRule`, `AccountRepository`, bağlam repository'leri (vehicle, shipment, warehouse, driver), `AccountDocumentTypeRepository`, `StoredFileRepository`, `AuditService`, `Clock`.

#### 3.2.1 `create(SaveExpenseRequest r, String idempotencyKey)` (`@Transactional`)
1. **Idempotency.** `idempotencyKey != null` ve `findByIdempotencyKey` varsa: `scope.requireVisible(existing.branchId)` ve mevcut kayıt döner (yeni yazım yok).
2. **Kapsam.** Controller `scope.requireNew(r.branchId)` çağırmıştır. `companyId = companies.companyOf(r.branchId)`.
3. **Kalem.** Yoksa 404 `EXPENSE_ITEM_NOT_FOUND`; `!active` ise 422 `EXPENSE_ITEM_INACTIVE`.
4. **Bağlam.**
   - `contextType`'a göre tam bir id dolu olmalı, diğerleri null; aksi halde 400 `EXPENSE_CONTEXT_INVALID`.
   - Kayıt yoksa 404 `EXPENSE_CONTEXT_NOT_FOUND`.
   - Bağlam kaydının şubesi: vehicle/driver `branch_id` null olabilir; warehouse ve shipment için zorunlu. Şube doluysa ve `companyOf(contextBranch) ≠ companyId` ise 422 `COMPANY_MISMATCH` ("Bağlam kaydı başka şirkete ait.").
5. **Belge türü.** `account_document_type` içinde `side='PAYABLE'`, `selectable`, `active`, `NOT penalty` olmalı; aksi halde 400 `DOCUMENT_TYPE_INVALID`.
6. **Satırlar.** 1–100 satır olmalı, aksi halde 400 `EXPENSE_LINES_REQUIRED`. Hesap `ExpenseCalculator` ile yapılır (§3.2.3). İstemcinin türettiği alanlar istenmez.
7. **Ödeme şekli.**
   - **ACCOUNT:**
     - `supplierAccountId` yoksa 400 `EXPENSE_SUPPLIER_REQUIRED`; `fundAccountId` doluysa 400 `EXPENSE_FUND_NOT_ALLOWED`.
     - Cari yok ya da pasifse 404 `ACCOUNT_NOT_FOUND`.
     - `type == EMPLOYEE` ise 422 `EXPENSE_SUPPLIER_INVALID`.
     - `identityRule.require(account, companyId)`.
   - **CASH/BANK:**
     - `fundAccountId` yoksa 400 `EXPENSE_FUND_REQUIRED`; `supplierAccountId` doluysa 400 `EXPENSE_SUPPLIER_NOT_ALLOWED`.
     - Fon şirketi ≠ `companyId` ise 422 `COMPANY_MISMATCH`.
     - Fon türü/para birimi uyumunu SS doğrular; hata kodları aynen yükselir.
8. **Kur.** `conv = rates.convert(new Money(total, currency), invoiceDate, r.exchangeRate)`. `exchange_rate = conv.rate`, `rate_date = conv.rateDate`, `tl_amount = conv.tlAmount`.
9. **Kayıt.** `expense` (POSTED, `idempotency_key`) + satırlar kaydedilir, ardından `flush`.
10. **Defter.** Açıklama: `"{kalem adı} masrafı"` + (`invoiceNumber` doluysa `" - " + invoiceNumber`), `LedgerDescriptions.fit` ile kısaltılır.
    - **ACCOUNT:** `ledger.post(new Posting(supplier, branchId, CREDIT, total(), invoiceDate, açıklama, "EXPENSE", id, conv.rate))`.
    - **CASH/BANK:** `s = settlements.create(PAYMENT, new SettlementRequest(method == CASH ? CASH : BANK, null, branchId, fundAccountId, expenseItemId, null, null, total(), invoiceDate, açıklama, conv.rate), "EXPENSE:" + id, null)`, ardından `expense.linkSettlement(s.getId())`. Bu settlement kaynak yönetimlidir: Ödemeler ekranından iptal edilemez (§3.0 kilidi, §3.6).
11. **Denetim.** `audit.record(EXPENSE_CREATED, "EXPENSE:"+id, "method="+method+",total="+total+currency)`.
12. **Eşzamanlı idempotency yarışı.** `DataIntegrityViolationException` (`expense_idempotency_uq`) → işlem geri alınır, `findByIdempotencyKey` sonucu döner. Controller'da tek yeniden deneme yapılır; `SettlementService.createByUser` deseni.

#### 3.2.2 `reverse(id, ReverseExpenseRequest{date, reason})` ve `revise(id, ReviseExpenseRequest)`
- **`reverse`:**
  - `lockById(id)`; yoksa 404 `EXPENSE_NOT_FOUND`.
  - `scope.requireVisible(branchId)`.
  - Zaten REVERSED ise mevcut detay döner (idempotent, 200).
  - `date < invoiceDate` ise 400 `REVERSE_DATE_INVALID`.
  - ACCOUNT: `ledger.reverseSource("EXPENSE", id, date, "İptal: " + reason)`. LS kuralı aynen geçer: 409 `TRANSACTION_TRANSFERRED`.
  - CASH/BANK: `settlements.reverseManaged(settlementId, date, reason)`.
  - `expense.reverse(date, reason)` ve `audit EXPENSE_REVERSED`.
- **`revise`** (Edit sayfası; Rev 1 F5):
  1. **Idempotency önce.** `idempotencyKey != null` ve `findByIdempotencyKey(key)` varsa: `scope.requireVisible(existing.branchId)`; `existing.replacesExpenseId ≠ id` ise 409 `IDEMPOTENCY_KEY_REUSED` ("Bu istek anahtarı başka bir kayıt için kullanıldı."); eşitse mevcut yeni kayıt döner (201, yeni yazım yok). Ağ kopması ya da çift tıklamayla yinelenen istek böylece aynı yeni id'yi alır.
  2. `lockById(id)`; yoksa 404 `EXPENSE_NOT_FOUND`; `scope.requireVisible`. Yalnız POSTED düzeltilebilir; REVERSED kayıt (anahtar eşleşmediyse) 409 `EXPENSE_ALREADY_REVERSED`.
  3. Tek işlemde eski kayıt ters çevrilir: tarih `max(today, old.invoiceDate)`, gerekçe `"Düzeltme: " + reason`. `REVERSE_DATE_INVALID` kuralı bu tarihle hiç tetiklenmez; ileri tarihli faturası olan masraf da düzeltilebilir.
  4. Yeni `create(r.expense, idempotencyKey)` yapılır; yeni kayıtta `replaces_expense_id = id`.
  - `r.removeDocument == false` ise `storedFiles.reassignOwner("EXPENSE", id, newId)`. `true` ise dosyalar eski (görünmez) kayıtta kalır; fiziksel silme yapılmaz.
  - `audit EXPENSE_REVISED("EXPENSE:"+newId, "replaces="+id)`.
  - Yeni kayıtta CASH/BANK varsa ya da eski kayıt CASH/BANK ise `FINANCE_PAYMENT_CREATE` gerekir (§4.2).

#### 3.2.3 Hesap kuralları (`ExpenseCalculator`; FE `expenseFormLogic.ts` aynısı)
Satır başına, ara sonuçlar 2 haneye `HALF_UP` yuvarlanır:
- `sub_total = round2(quantity × unit_price)`
- `discount_amount = round2(sub_total × discount_rate / 100)`
- `net_amount = sub_total − discount_amount`
- `vat_amount = round2(net_amount × vat_rate / 100)`
- `total_amount = net_amount + vat_amount + other_tax_amount − withholding_amount` (**ZTO hatası düzeltildi**: diğer vergiler eklenir)

Doğrulamalar:
- `withholding_amount > vat_amount` → 400 `WITHHOLDING_EXCEEDS_VAT`.
- Satır `total_amount < 0` → 400 `AMOUNT_INVALID`.

Başlık: her alan satır toplamıdır. Başlık `total_amount ≤ 0` ise 400 `AMOUNT_INVALID`.

#### 3.2.4 Kapsam ve şirket kuralları
- Yazımda gövdedeki `branchId` → controller `scope.requireNew`. Var olan kayıt → `scope.requireVisible(expense.branchId)`.
- Okumada `scope.filter(companyId, branchIds)` kullanılır. LIMITED kullanıcıda boş liste kendi iş yerlerine daralır; kapsam dışı `branchIds` 403 verir.
- `companyId` süzgeci bütün liste, özet, takvim ve aylık uçlarında vardır (`BranchFilter`).
- Şirket kaynağı her zaman `companyOf(branchId)` sonucudur. İstemci `companyId` göndermez (form gövdesinde yok).

#### 3.2.5 Eşzamanlılık ve kilit sırası
`expense` satırı (`lockById`) → (SS) `settlement` kilidi → `account_transaction` kilidi (`LS.reverse` içinde). İki eşzamanlı `reverse` çağrısından ikincisi kilidi bekler ve REVERSED'i görüp idempotent döner. `create` yarışını tekil idempotency indeksi çözer.

#### 3.2.6 Okuma sorguları (`ExpenseQueryRepository`, native; hepsi `e.deleted = false`)
- **`list(f)`:** sayfalı. Süzgeçler `expenseItemId`, `currency`, `from`/`to` (`invoice_date`), `companyId`, `branchIds`. Join'ler kalem, tür, `branch.name`, `account.name` (tedarikçi) ve bağlam etiketidir: `vehicle.plate` / `shipment.number` / `warehouse.name` / `driver.full_name`. `hasDocument` = `exists(stored_file owner_type='EXPENSE' and owner_id=e.id and deleted=false)`. Sıralama `invoice_date desc, created_at desc`.
- **`summary(f)`:** `expense_item_id` bazında. Alanlar:
  - kalem ad/kod/tür;
  - para birimi başına `count` ve `sum(total_amount)`;
  - `max(invoice_date)`;
  - `array_agg(distinct branch.name)`;
  - son tedarikçi: `invoice_date desc, created_at desc` ile ilk ACCOUNT kaydının `account.id`, `name`, `tax_number_masked`, `phone` ve `city` alanları. TCKN/VKN düz gönderilmez.
- **`calendar(year, month, f)`:** ayın kayıtları, gün bazında gruplanır.
- **`allTime(f)`:** para birimi başına `count` ve `net`/`vat`/`discount`/`total` toplamları.
- **`monthly(months, f)`:** son N ay (bu ay dahil), `to_char(invoice_date,'YYYY-MM')` × `expense_type` için `sum(tl_amount)`.
- **`contextOptions(type, q, branchId)`:** en çok 20 satır; `q` ile `ILIKE` araması:
  - VEHICLE: `vehicle.plate`;
  - SHIPMENT: `shipment.number`, son 365 gün, CANCELLED hariç;
  - WAREHOUSE: `warehouse.name`;
  - DRIVER: `driver.full_name` (yalnız ad; telefon yok).
  Satır şubesi şirket uyumu için döner. Şirket süzgeci: `companyOf(branchId)` ile aynı şirketteki ya da şubesiz kayıtlar.

### 3.3 `SubcontractCostService` (B3, yeni; `BE/shipment/service/SubcontractCostService.java`)
Bağımlılıklar: `ShipmentService` (`lock`), `ShipmentLegRepository`, `TripCostRepository`, `AccountRepository`, `CompanyResolver`, `CompanyIdentityRule`, `BranchScopeService`, `ExchangeRateService`, `LedgerService`, `AccountDocumentTypeRepository`, `AccountTransactionRepository` (açık plan denetimi), `AuditService`, `Clock`.

#### 3.3.1 `save(shipmentId, legId, SaveSubcontractCostRequest r)` (`@Transactional`)
1. `shipment = shipmentService.lock(shipmentId)`, ardından `scope.requireVisible(shipment.branchId)`. `CANCELLED` ise 409 `SHIPMENT_CANCELLED`. CLOSED sefere de girilebilir.
2. `leg`: yoksa ya da `leg.shipmentId ≠ shipmentId` ise 404 `LEG_NOT_FOUND`. `carrierAccountId == null` ise 409 `LEG_NOT_SUBCONTRACTED`.
3. `companyId = companyOf(shipment.branchId)`, `account = accounts.findById(carrier)`, `identityRule.require(account, companyId)`.
4. Doğrulama:
   - `money.amount > 0`; `vat`, `wh` ve `ded` ≥ 0 olmalı.
   - `wh > vat` → 400 `WITHHOLDING_EXCEEDS_VAT`.
   - `payable ≤ 0` → 400 `AMOUNT_INVALID`.
   - `documentType` null değilse PAYABLE/selectable/active/!penalty olmalı; aksi halde 400 `DOCUMENT_TYPE_INVALID`.
   - `costDate` zorunlu.
5. `active = costs.findByLegIdAndKindOrderByCreatedAt(legId, SUBCONTRACTOR)`:
   - `size > 1` → 409 `COST_DUPLICATE` ("Bu etapta birden çok taşeron gideri var; sefer ekranından düzeltin.").
   - Satırın `accountId ≠ carrier` ise 409 `CARRIER_MISMATCH`.
6. `conv = rates.convert(r.money, r.costDate, r.exchangeRate)`.
7. Duruma göre:
   - **Satır yok:** `new TripCost(shipmentId, legId, SUBCONTRACTOR, carrier, null, money, conv.tl, açıklama)` + `updateSubcontract(…)` → kaydet → **post** (adım 8).
   - **OPEN:** `updateSubcontract(…)` → **post**.
   - **POSTED:**
     - `sameSubcontract(r)` ise no-op, mevcut satır döner (idempotent PUT).
     - Aksi halde açık plan denetimi: `existsOpenPlanForTripCost(old.id)` (`FinanceRepositories.OPEN_PLAN` TRIP_COST dalıyla aynı koşul) → 409 `COST_PLAN_OPEN` ("Bu gidere bağlı açık ödeme planı var; önce planı iptal edin.").
     - Plan yoksa: `ledger.reverseSource("TRIP_COST", old.id, r.costDate, "Düzeltme: " + shipment.number)`; yeni satır kaydedilir; `old.reverse(r.costDate, "Düzeltme", new.id)`; yeni satır **post** edilir.
8. **post:** `ledger.post(new Posting(carrier, shipment.branchId, CREDIT, new Money(cost.payable(), currency), r.costDate, shipment.number + " taşeron nakliye" + (docNo != null ? " " + docNo : ""), "TRIP_COST", cost.id, conv.rate))`, ardından `cost.markPosted(clock.instant())` ve `audit TRIP_COST_POSTED("TRIP_COST:"+id, "payable="+…)`.
9. `r.transportMode` doluysa `leg.changeTransportMode(…)`. ZTO formu göndermez; alan API için vardır.

#### 3.3.2 `reverse(costId, ReverseCostRequest{date, reason})` (`@Transactional`)
- `lockById`; yoksa 404 `COST_NOT_FOUND`.
- `shipmentService.lock(cost.shipmentId)` (kilit sırası: önce sefer, sonra maliyet; `lockById` sefer kilidinden sonra yeniden okunur) ve `scope.requireVisible`.
- `kind ≠ SUBCONTRACTOR` → 409 `COST_NOT_REVERSIBLE`.
- REVERSED ise 204 (idempotent).
- OPEN ise 409 `COST_NOT_POSTED` ("Yazılmamış gider silinir": FE bu durumda `DELETE /shipment/subcontract-costs/{costId}` çağırır, §3.3.2a).
- Açık plan denetimi → 409 `COST_PLAN_OPEN`.
- `ledger.reverseSource("TRIP_COST", id, date, "İptal: " + reason)`, ardından `cost.reverse(date, reason, null)` ve `audit TRIP_COST_REVERSED`.

#### 3.3.2a `remove(costId)` (`@Transactional`; Rev 1 F6)
Finans kullanıcısının (FINANCE/FINANCE_SUPER; `SHIPMENT_DISPATCH` yok, V2:119 yalnız OPERATIONS) OPEN taşeron gideri silmesi için. Mevcut `DELETE /shipment/costs/{id}` (`SHIPMENT_DISPATCH`) değişmez.
- `findAnyById`; yoksa 404 `COST_NOT_FOUND`. `shipmentService.lock(cost.shipmentId)`, ardından `lockById` ile yeniden okuma ve `scope.requireVisible`.
- `kind ≠ SUBCONTRACTOR` → 409 `COST_NOT_REVERSIBLE`.
- REVERSED ya da `deleted` → 204 (idempotent).
- POSTED (ya da `postedAt != null`) → 409 `COST_POSTED` ("Cariye işlenmiş gider silinemez; ters kayıt yapın.").
- OPEN → `cost.markDeleted()`; defter etkisi yok; `audit TRIP_COST_REVERSED("TRIP_COST:"+id, "deleted-open")`.

### 3.4 Taşeron okuma (B3; `SubcontractQueryRepository` native + `SubcontractCostService.summary/detail`)
- **Taban:** `shipment_leg l join shipment s on s.id = l.shipment_id join branch b on b.id = s.branch_id`. Koşullar:
  - `l.deleted = false and s.deleted = false and l.carrier_account_id is not null and s.status <> 'CANCELLED'`;
  - `l.planned_start >= now() - (:days || ' days')::interval` (`days` 1–365, vars. 150, aksi halde 400 `DAYS_INVALID`);

  Maliyet: `left join trip_cost c on c.leg_id = l.id and c.kind = 'SUBCONTRACTOR' and c.deleted = false`.
- **`summary`:** `l.carrier_account_id` bazında gruplanır. Alanlar:
  - `account.name`, `account.code`, `account.phone`, `account.city`, `account.district` (adres şifreli, gönderilmez);
  - `string_agg(distinct company.name)` (Şirket Adı = seferin şirketi; OK-12.7-12);
  - `count(*)` etap;
  - para birimi başına `sum(c.amount)` (net) ve `sum(payable)`.
  Genel toplam: firma sayısı, etap sayısı, para birimi başına toplam.
- **`detail(carrierAccountId)`:** etap başına bir satır (maliyet yoksa maliyet alanları null). Alanlar:

## 10. Modern Web Guidance (bu belgede kullanılan kılavuzlar)
- **`forms`:** §5.0, §5.4, §5.6 ve §5.7'deki label/for, `aria-invalid`, `aria-describedby`, `blur`/`submit` zamanlaması, ilk hataya odak, geçerli gönderimden sonra düğme kilidi, `type="button"` yardımcı düğmeler ve `role="status"` duyurusu. Alıntı: "Validate on `blur` (if edited) to avoid premature warnings while typing, and reset error states on `input` as soon as the user fixes the value, and route the focus to the first error or summary on `submit`."
- **`capture-location-agnostic-data`:** fatura, vade, maliyet ve yükleme tarihleri saat dilimsiz `YYYY-MM-DD` dizgisi olarak işlenir; `new Date("YYYY-MM-DD")` yasaktır. Temporal, Limited availability ve yeni bağımlılık nedeniyle kullanılmaz (§5.10). Alıntı: "saving a date like `"1990-01-01"` can result in users west of UTC seeing `"1989-12-31"`".
- Aramalar: "repeatable form rows computed totals" (→ `forms` seçildi) ve "calendar month grid navigation" (→ `capture-location-agnostic-data` seçildi; `spatial-navigation` takvimde ok tuşu gezinmesi için uygun ama ertelendi).
