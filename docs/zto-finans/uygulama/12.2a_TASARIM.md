### 1.1 `MIG/V35__settlement_details.sql` (Z15)

```sql
-- Z15 · Faz 12.2a · MX7 V2xQ1 (gerçek adlarla) · 04 §6.2-Y9 · 12.2a_TASARIM §1.1
-- Ödeme/tahsilat ayrıntıları: belge no (serbest metin, tekil değil — MX7 Ç18), banka kanalı (kredi
-- kartı = BANK + CREDIT_CARD), karşı tarafın banka hesabı (yalnız FK; IBAN kopyalanmaz — KVKK),
-- düzeltme zinciri (düzeltme aynı şirkette), iptal tarihi ve gerekçesi.

-- 1. Karşı taraf banka hesabının settlement carisine ait olmasının veritabanı güvencesi.
ALTER TABLE account_bank_account
    ADD CONSTRAINT account_bank_account_id_account_uq UNIQUE (id, account_id);

-- 2. Kolonlar
ALTER TABLE settlement
    ADD COLUMN document_no                  VARCHAR(50),
    ADD COLUMN channel                      VARCHAR(20),
    ADD COLUMN counterparty_bank_account_id UUID,
    ADD COLUMN corrects_settlement_id       UUID,
    ADD COLUMN reverse_reason               VARCHAR(500),
    ADD COLUMN reversed_on                  DATE;

-- 3. Mevcut iptal edilmiş kayıtların iptal tarihi: cari ters satırı, yoksa fon ters satırı, o da
--    yoksa son güncelleme günü (İstanbul). Ters satır: source_type='REVERSAL', source_id = orijinal satır.
UPDATE settlement s
   SET reversed_on = COALESCE(
           (SELECT min(r.transaction_date)
              FROM account_transaction o
              JOIN account_transaction r ON r.source_type = 'REVERSAL' AND r.source_id = o.id
             WHERE o.source_type = 'SETTLEMENT' AND o.source_id = s.id),
           (SELECT min(r.transaction_date)
              FROM fund_transaction o
              JOIN fund_transaction r ON r.source_type = 'REVERSAL' AND r.source_id = o.id
             WHERE o.source_type = 'SETTLEMENT' AND o.source_id = s.id),
           (s.updated_at AT TIME ZONE 'Europe/Istanbul')::date)
 WHERE s.status = 'REVERSED';

-- 4. Kısıtlar
ALTER TABLE settlement
    ADD CONSTRAINT settlement_channel_ck
        CHECK (channel IS NULL OR (method = 'BANK' AND channel IN ('TRANSFER', 'CREDIT_CARD'))),
    ADD CONSTRAINT settlement_counterparty_account_ck
        CHECK (counterparty_bank_account_id IS NULL OR account_id IS NOT NULL),
    ADD CONSTRAINT settlement_counterparty_bank_fk
        FOREIGN KEY (counterparty_bank_account_id, account_id)
        REFERENCES account_bank_account (id, account_id),
    -- settlement_id_company_uq (V32:6) hedefi: düzeltme kaydı eskisiyle aynı şirkette.
    ADD CONSTRAINT settlement_corrects_fk
        FOREIGN KEY (corrects_settlement_id, company_id) REFERENCES settlement (id, company_id),
    ADD CONSTRAINT settlement_corrects_self_ck
        CHECK (corrects_settlement_id IS NULL OR corrects_settlement_id <> id),
    ADD CONSTRAINT settlement_reversed_on_ck
        CHECK ((status = 'REVERSED') = (reversed_on IS NOT NULL));

-- 5. İndeksler
-- Bir kayıt en çok bir kez düzeltilir (account_document_revised_from deseni).
CREATE UNIQUE INDEX settlement_corrects_uq
    ON settlement (corrects_settlement_id) WHERE corrects_settlement_id IS NOT NULL AND deleted = FALSE;
-- Ödeme/tahsilat listesi (tür + şirket + tarih) ve cari süzgeci.
CREATE INDEX settlement_list_idx ON settlement (type, company_id, settlement_date DESC) WHERE deleted = FALSE;
CREATE INDEX settlement_account_date_idx
    ON settlement (account_id, settlement_date DESC) WHERE deleted = FALSE AND account_id IS NOT NULL;
CREATE INDEX settlement_document_no_idx
    ON settlement (lower(document_no)) WHERE document_no IS NOT NULL AND deleted = FALSE;
CREATE INDEX settlement_counterparty_bank_idx
    ON settlement (counterparty_bank_account_id) WHERE counterparty_bank_account_id IS NOT NULL;
-- Araç gideri bağı denetimi (§3.5, SETTLEMENT_SOURCE_MANAGED).
CREATE INDEX vehicle_expense_settlement_idx
    ON vehicle_expense (settlement_id) WHERE settlement_id IS NOT NULL;
```

Notlar: `channel` geri doldurulmaz (eski BANK satırında NULL = "Banka Havalesi/Eft"); `document_no` geri doldurulmaz. Bileşik FK'ler `MATCH SIMPLE` — `counterparty_bank_account_id` NULL ise denetlenmez; `account_id` NULL iken dolu olması `settlement_counterparty_account_ck` ile engellenir.

-- 1. Bileşik FK hedefleri

### 3.5 İptal — `reverse` / `doReverse` değişiklikleri (B2)

`doReverse(UUID id, LocalDate date, String reason, ReverseMode mode)`; `enum ReverseMode { USER, INTERCOMPANY, MANAGED }`:
- `reverse(id, date, reason)` = `USER`; `reverseLinked` = `INTERCOMPANY` (mevcut); **yeni** `reverseManaged(id, date, reason)` = `MANAGED` (yalnız `VehicleExpenseService.reverse` çağırır; SS:139-140 çağrısı buna döner).
- **Personel (Rev 1 SEC-05):** `USER` kipinde `requireSettlementReadable(settlement)` — yeni özel yardımcı: `accountId != null` ise kart okunur (`accounts.findById`) ve `!access.employeeVisible() && account.type == EMPLOYEE` ise **404 `SETTLEMENT_NOT_FOUND`** ("Kayıt bulunamadı."). `access.readable` **kullanılmaz** (o 404 `ACCOUNT_NOT_FOUND` atar ve kaydın personel carisine ait olduğunu sızdırır). Aynı yardımcı `correct` (eski kayıt + idempotent tekrar), `check?correctsSettlementId` ve `detail` yollarında kullanılır; IT'ler hata **kodunu** doğrular.
- **Cari taşıma (Rev 1 F-2):** `USER` kipinde, kilitlerden sonra, settlement'ın cari satırının aktif `account_transfer_line` kaydı varsa 409 `TRANSACTION_TRANSFERRED` "Cari taşıma geri alınmadan düzenlenemez/silinemez." (erken ve açık ileti; `LedgerService.reverse` aynı denetimi zaten yapar, burada katalogdaki kodla önce yakalanır). `SettlementRepository.isTransferred(id)` (B2) = `exists(select 1 from account_transaction t join account_transfer_line l on l.account_transaction_id = t.id and l.active and l.deleted = false where t.source_type = 'SETTLEMENT' and t.source_id = :id)`.
- **Tarih kuralı** (yalnız `USER`; 12.2 transfer kuralı): `settlement_date ≤ date ≤ max(clock.today(), settlement_date)`; küçükse 400 `REVERSE_BEFORE_SETTLEMENT` "İptal tarihi ödeme/tahsilat tarihinden önce olamaz."; büyükse 400 `DATE_IN_FUTURE`. `clock` = `TenantClock.today()`.

(Rev 1 F-2).
6. Yeni istek: `replacement.method ∉ {CASH, BANK}` → 400 `CORRECTION_METHOD_INVALID`; `companies.companyOf(replacement.branchId) != old.companyId` → 422 `COMPANY_MISMATCH` "Düzeltme aynı şirkette yapılır; başka şirkete taşımak için kaydı silip yeni kayıt girin." Cari değişebilir (ZTO düzenlemesi gibi), tür değişemez (uç türü eski kaydın türüdür).

Kilitler (§3.11): yeni cari kartı FOR SHARE (`usableLocked`, + kimlik kuralı) → fonlar `fundAccounts.lockAll([old.fund, new.fund])` (`FundAccountRepository.lockAll`, id sırası) → eski settlement `entityManager.refresh(old, PESSIMISTIC_WRITE)` → **eşzamanlı idempotent tekrar (Rev 1 F-6):** `findByCorrectsSettlementId(id)` doluysa ve o kaydın `idempotency_key`'i istekteki anahtara eşitse (anahtar null değil) onu döndür (adım 2'nin kapsam/personel denetimleri onun için de yapılır), değilse adım 4–5 yeniden (durum yarışı; 409) → yeni fon aktif (422 `FUND_INACTIVE`) → `validate(type, replacement, false)` → eşleştirme doğrulaması (`excludedSettlementId = id`, hedef kilitleri burada).

10. Dönüş: yeni `Settlement` (controller 201 + `SettlementResponse`).

Salt metin değişikliği (yalnız açıklama/belge no) de düzeltme ile yapılır (OK-12.2a-5). Eski kaydın eşleşmeleri yeni kayda **kopyalanmaz**; istemci eski eşleşmeleri forma önyükler ve istekte gönderir.

### 3.11 Kilit sırası ve eşzamanlılık

12.2 §3.10 sabit sırası genişler: **(1) cari kartları** (FOR SHARE `usableLocked`) → **(2) fonlar** (`funds.lockAll`, id sırası, FOR UPDATE) → **(3) settlement** (`refresh PESSIMISTIC_WRITE`; yalnız reverse/correct) → **(4) FX kaynak satırları** (yalnız bozum) → **(5) eşleştirme hedefleri** (danışma kilidi, `targetId` sırası) → **(6) belge serisi** → yazımlar.

| Yol | Sıra |
|---|---|
| Oluşturma (`createByUser`) | cari FOR SHARE → **`fundAccounts.lockAll([istek fonu])` (gate adım 2a; Rev 1 F-1)** → hedef danışma kilitleri → yazım (FLS `findForUpdate` aynı fonu yeniden kilitler, bekleme yok). Sıra genel sıraya (1)→(2)→(5) uyar; `correct` ile ters sıra kalmaz. Fatura iptali hedef kilidi almadığından döngü yok. |
| `reverse` | mevcut (settlement kilitsiz → fon → settlement) |
| `correct` | yeni cari FOR SHARE → `fundAccounts.lockAll(eski fon, yeni fon)` → eski settlement FOR UPDATE → hedef danışma kilitleri → (PAYMENT) ters + flush + uyarı + yeni; (COLLECTION) yeni + ters |
| Döviz bozumu oluşturma ∥ `correct` | ikisi de fon → settlement sırası; `correct` settlement kilidinden sonra `existsActiveBySettlementId` yeniden okunur → biri 409 |

Eşzamanlılık IT'leri (`CyclicBarrier`, §6.2): iki tahsilat aynı faturaya kalanın tamamını eşleştirir → biri 201, diğeri 422 `ALLOCATION_EXCEEDS_REMAINING`; **aynı fon + aynı fatura: `createByUser` (eşleştirmeli) ∥ `correct` (eşleştirmeli) → biri 201, diğeri 201 ya da 422 `ALLOCATION_EXCEEDS_REMAINING`** (Rev 1 F-1); aynı kaydın iki düzeltmesi (farklı anahtar) → biri 201, diğeri 409 `SETTLEMENT_ALREADY_CORRECTED`/`SETTLEMENT_REVERSED`; **aynı kaydın aynı anahtarla iki düzeltmesi → ikisi de 201, aynı yeni kimlik** (Rev 1 F-6); düzeltme ∥ döviz bozumu → biri başarılı, diğeri 409; hiçbirinde 40P01/500 yok.

## 4. REST sözleşmesi

Kök `/api/v1/finance`. İzinler: **VIEW** = `FINANCE_VIEW`, **POST** = `FINANCE_PAYMENT_CREATE`. Tüm uçlar kiracı şemasında ve `BranchScopeService` kapsamında. Tarihler ISO `YYYY-MM-DD`, zaman damgası ISO-8601 `Instant`.

**Para ve ondalık serileştirmesi (Rev 1 F-5/SEC-04):** `Money {amount: string, currency: string}` — `Money.amount` JSON'da **ondalık metindir** (`"1500.25"`; `common/money/Money.java` `@JsonFormat(shape = STRING)` + `@Schema(type = "string", format = "decimal")`; TS `interface Money { amount: string }`). Bu belgede **yeni** eklenen çıplak `BigDecimal` para alanları da aynı biçimdedir ("decimal" yazılır): Java'da `@JsonFormat(shape = JsonFormat.Shape.STRING) @Schema(type = "string", format = "decimal")`, TS'de `string` — `AllocationRequest.amount` (istek; Jackson metni de sayıyı da kabul eder, istemci metin gönderir), `OpenInvoiceResponse.total/allocated/remaining`, `SettlementListItemResponse.fxUsed/fxRemaining`, `DailyFundBalanceResponse.balanceAtDate/balanceNow`, `DailyInstrumentMovementResponse.total`. Kur ve TL karşılığı (`exchangeRate`, `tlAmount`) mevcut DTO'larla aynı kalır: JSON **number**, TS `number` (yalnız gösterim; hesaba girmez). İstemci tutar toplamı/karşılaştırması (`allocationLogic`, `settlementFormLogic`, `dailyReportLogic`, `settlementListLogic.fxCell`) float ile **yapılmaz**: FE-0'ın `FE/zto/decimal.ts` yardımcısı (10⁴ ölçekli `bigint`: `toScaled`, `addDec`, `subDec`, `cmpDec`, `minDec`, `fromScaled`, `sumDec`) kullanılır.
