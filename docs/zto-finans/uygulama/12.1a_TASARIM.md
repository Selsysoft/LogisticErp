### 0.2 12.1a'nın sonunda ne olur

1. Her kiracıda bir **varsayılan şirket** vardır (göçle oluşur; adı `admin.tenant.name`, VKN/vergi dairesi/adres eski `edocument_settings`'ten). Tek şirketli kiracıda hiçbir ekran ve API davranışı değişmez (§1.3).
2. Kiracı 2–3 şirket açabilir (plan limiti `max_companies`). Her şirketin unvanı, VKN/TCKN'si, logosu, e-belge ayarı ve navlun/depo faturası serisi ayrıdır.
3. Para ve yasal belge tablolarının her satırı bir şirkete aittir (`company_id` + bileşik FK). Şirketler arası tutarsız kayıt (başka şirketin kasasına tahsilat vb.) 422 `COMPANY_MISMATCH` ile reddedilir.
4. Kullanıcı, iş yeri kapsamıyla (`ALL` / `LIMITED`) sınırlanabilir; kapsam sunucuda uygulanır (§4.15–§4.16).
5. ZTO görünümlü üç tanım ekranı (İş Yerleri, Şubeler, Şirketler) ve MUI'de aktif şirket seçici + kullanıcı "İş Yeri Yetkisi" sekmesi vardır.

## 2. Migration'lar

### 2.0 Genel kurallar ve `admin.tenant` erişim kanıtı

- Numaralar: Z01→`V22__company.sql`, Z02→`V23__branch_group_and_branch_details.sql`, Z03→`V24__company_scope_columns.sql`, Z04→`V25__document_series.sql`, Z05→`V26__user_branch_scope.sql` (`MIG/tenant`); ZA1→`V8__plan_company_limits.sql` (`MIG/admin`). Son mevcut: tenant V21, admin V7.
- Flyway her migration'ı tek işlemde çalıştırır (PostgreSQL DDL işlemseldir). **Göç hatasının sonucu ağırdır:** `TenantMigrationRunner` (`BE/tenant/service/TenantMigrationRunner.java:28-44`) açılışta yalnız `ACTIVE` ve `SUSPENDED` kiracıları tarar; hata alan kiracıyı `tenant.markFailed(); tenants.save(tenant)` ile **FAILED** yapar. `TenantFilter.java:74-75` ACTIVE olmayan her kiracıya 403 `TENANT_NOT_ACTIVE` döner → kiracının **tamamı** erişilemez. FAILED kiracı sonraki açılışlarda taranmadığı için düzeltilmiş sürümle de **kendiliğinden yeniden denenmez**; SUSPENDED iken düşen kiracı askı bilgisini kaybeder. Bu yüzden migration'lar **veriye bağlı düşmeyecek** biçimde yazılır (boş tablo, NULL, geçersiz VKN, silinmiş satır) ve kurtarma prosedürü §9.4'tedir.
- **Dondurma kuralı (ajanlar için bağlayıcı):** V22–V26 ve admin V8, B1 teslim edildiği anda **dondurulur**. B1 sonrasında yerel dev DB'ye (docker compose, dev backend, Playwright) uygulanmış bir dosyanın düzenlenmesi Flyway `validateOnMigrate` checksum uyuşmazlığı verir ve sonraki açılışta dev kiracılarının hepsi FAILED olur. B2–B5'te gereken her şema düzeltmesi **yeni dosyayla** (`V27__…`, sıradaki boş numara; Z-kimliği koordinatörden) yapılır; var olan dosya düzenlenmez. B1 kendi içinde (teslimden önce) düzenleyebilir; bu durumda yerel dev şemasını `flyway repair` ya da şemayı silip yeniden açarak temizler.
- Kiracı erişimi Hibernate `SchemaConnectionProvider` ile yapılır; `JdbcTemplate` kiracı şemasını **bilmez**. Kiracı verisine Java'dan yalnız JPA/repository (gerekirse native `@Query`) ile erişilir.
- `gen_random_uuid()` PG 13+ çekirdek (PG 16 kullanılıyor). `UNIQUE NULLS NOT DISTINCT` PG 15+.
- **`admin.tenant` erişimi — kanıt:** (1) `TenantMigrator.migrate` (`BE/tenant/service/TenantMigrator.java:17-24`) uygulamanın tek `DataSource`'unu kullanır, `.schemas(schema).defaultSchema(schema)` ile `search_path` kiracı şemasıdır → `current_schema()` kiracı şema adını verir. (2) Admin şeması aynı veritabanında, adı sabit `admin` (`application.yml` `spring.flyway.schemas: admin`). (3) `TenantService.create` `@Transactional` değildir; `tenants.save` (`:74`) `migrate` (`:76`) çağrısından önce commit edilir → yeni kiracı açılışında satır görünür; mevcut kiracılarda satır zaten vardır. (4) Testcontainers'ta admin Flyway açılışta çalışır, testler kiracıyı `/api/v1/admin/tenants` ile açar. **Kanıtlanmayan:** ayrı veritabanı senaryosu (desteklenmez; olursa ad `Şirket` düşer, göç bozulmaz). Koruma: `to_regclass('admin.tenant')` + `EXECUTE` (statik referans yok). Test (§7.1 G-3) satırı olmayan şemayı doğrular.
- Denetim kolonları her yeni tabloda `created_by/updated_by VARCHAR(254)`, `created_at/updated_at TIMESTAMPTZ`; göçte `'system'`, `now()`.

    code                    VARCHAR(20)  NOT NULL,
    title                   VARCHAR(300) NOT NULL,
    short_name              VARCHAR(100) NOT NULL,
    tax_id_type             VARCHAR(4)   NOT NULL DEFAULT 'VKN',
    tax_number              VARCHAR(11),
    tax_office              VARCHAR(100),
    mersis_no               VARCHAR(16),
    trade_registry_no       VARCHAR(50),
    sgk_workplace_no        VARCHAR(26),

    postal_code             VARCHAR(10),
    country                 CHAR(2)      NOT NULL DEFAULT 'TR',
    phone                   VARCHAR(30),
    email                   VARCHAR(254),
    kep_address             VARCHAR(254),
    website                 VARCHAR(200),
    logo_file_id            UUID REFERENCES stored_file (id),
    default_fund_account_id UUID,                      -- bileşik FK V24'te (fund_account.company_id sonrası)
    is_default              BOOLEAN      NOT NULL DEFAULT FALSE,
    active                  BOOLEAN      NOT NULL DEFAULT TRUE,
    update_count            INTEGER      NOT NULL DEFAULT 0,
    created_by              VARCHAR(254) NOT NULL,
    created_at              TIMESTAMPTZ  NOT NULL,
    updated_by              VARCHAR(254) NOT NULL,

    CONSTRAINT company_tax_id_type_ck CHECK (tax_id_type IN ('VKN', 'TCKN')),
    CONSTRAINT company_tax_number_ck CHECK (
        tax_number IS NULL
        OR (tax_id_type = 'VKN' AND tax_number ~ '^[0-9]{10}$')
        OR (tax_id_type = 'TCKN' AND tax_number ~ '^[1-9][0-9]{10}$')),
    CONSTRAINT company_mersis_ck CHECK (mersis_no IS NULL OR mersis_no ~ '^[0-9]{16}$'),
    CONSTRAINT company_default_active_ck CHECK (NOT is_default OR active)

CREATE UNIQUE INDEX company_tax_number_uq ON company (tax_number)
    WHERE deleted = FALSE AND tax_number IS NOT NULL;

CREATE UNIQUE INDEX company_default_uq ON company (is_default) WHERE is_default AND deleted = FALSE;

-- ZTO ZT_UyumsoftSetting karşılığı (Views/Uyumsoft/Settings.cshtml:50-156). 12.1a'da yalnız saklanır;

CREATE TABLE company_edocument_settings (

    enabled          BOOLEAN      NOT NULL DEFAULT FALSE,
    test_mode        BOOLEAN      NOT NULL DEFAULT TRUE,
    service_url      VARCHAR(300),

    password_enc     VARCHAR(500),
    default_profile  VARCHAR(20)  NOT NULL DEFAULT 'TICARIFATURA',
    invoice_series   VARCHAR(3),
    despatch_series  VARCHAR(3),
    despatch_enabled BOOLEAN      NOT NULL DEFAULT FALSE,
    inbox_enabled    BOOLEAN      NOT NULL DEFAULT FALSE,
    inbox_last_sync  TIMESTAMPTZ,
    created_by       VARCHAR(254) NOT NULL,
    created_at       TIMESTAMPTZ  NOT NULL,
    updated_by       VARCHAR(254) NOT NULL,
    updated_at       TIMESTAMPTZ  NOT NULL,
    CONSTRAINT company_edocument_profile_ck
        CHECK (default_profile IN ('TICARIFATURA', 'TEMELFATURA', 'EARSIVFATURA')),
    CONSTRAINT company_edocument_invoice_series_ck
        CHECK (invoice_series IS NULL OR invoice_series ~ '^[A-Z0-9]{3}$'),
    CONSTRAINT company_edocument_despatch_series_ck
        CHECK (despatch_series IS NULL OR despatch_series ~ '^[A-Z0-9]{3}$')

-- COMPANY_MANAGE: PATRON koddan otomatik alır (Role.getEffectivePermissions); FINANCE_SUPER tohumlanır.

Tüm yollar `/api/v1` öneklidir. Tipler: `UUID` ve `Instant` → JSON string; `BigDecimal` → number; `LocalDate` → `"yyyy-MM-dd"`. Sayfalı yanıt mevcut `PageResponse {content, page, size, totalElements, totalPages}`. Record adları = OpenAPI şema adları (springdoc basit sınıf adı); ön yüz tipi `X` ↔ şema `X` ya da `XResponse` (contract.test kuralı).
